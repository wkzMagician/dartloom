# Dartloom CLI

Configuration-driven lifecycle tooling for Dartloom Flutter applications.

```bash
dart install --overwrite https://github.com/wkzMagician/dartloom.git --git-path cli/dartloom_cli
dartloom new my_app
cd my_app
dartloom cap
```

After pub.dev publication, install with `dart install dartloom`. Use
`dartloom self-update` to refresh the CLI and `dartloom project upgrade` to migrate
schema v1 or refresh only Dartloom-owned capability glue. The project upgrade
always runs `flutter pub upgrade`, so Git locks cannot retain an older
contract API; it never overwrites `lib/app` or existing ARB translations.

The interactive `dartloom cap` editor manages named capability instances,
official/custom implementations, adapter options, sync storage selection, and
WebDAV configuration. `${NAME}` options become required Dart defines.

Use `dartloom project upgrade --source=github` during repository development
and `dartloom project upgrade --source=pub` after selected packages are available
on pub.dev. Run
`dartloom --help` for build, installer, and unsupported-platform details.

Projects generated by the CLI include a reusable release workflow. Every push
to `main` attempts enabled release builds and uploads artifacts; a `v*` tag also
creates a GitHub Release. The generated workflow follows the Dartloom
repository's `main` branch.
